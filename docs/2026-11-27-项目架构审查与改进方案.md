# 拾焰项目架构审查与改进方案

审查基线为 2026-11-27 的 `main`，提交 `e784adc`。范围包括念头、目标、火种、设置、状态与存储、AI 润色，以及 PWA 和单文件两种交付方式。

## 结论

当前的 React、TypeScript、Vite 和 IndexedDB 组合适合本地优先的个人手记。页面已按业务组织，弹层、导航和反馈有共用组件，目标与念头列表也已有分段渲染。应保留这些边界和现有技术栈。

首要问题是**数据已经显示为保存成功，后续仍可能被空状态、旧快照或启动时的归一化覆盖**。这几条路径已在本机复现。建议先保护旧数据、统一备份与运行时的数据契约，再收拢编辑、删除和 AI 的状态处理。目录调整随实际职责迁移进行。

| 优先级 | 发现 | 建议 |
| --- | --- | --- |
| P1 | 读取失败可用空状态覆盖原数据，备用存储的较新写入可被忽略 | 区分首次使用、恢复和故障，定义主副本提交与恢复规则 |
| P1 | 同源标签页互相覆盖，快速刷新会丢掉念头的最后一段编辑 | 按基准修订号提交，只保存实际改动，统一编辑提交入口 |
| P1 | 启动与导入静默裁剪，应用能导出超过自身导入上限的文件 | 分开启动解码、版本迁移和导入预览，保证备份往返 |
| P2 | 删除、撤回、导入与清空的生效规则散在组件里 | 以完整的数据操作处理，按真实结果更新界面 |
| P2 | AI 流结束不完整时仍允许替换，旧请求可能影响新请求 | 统一请求生命周期，区分完整结果、片段和失败 |
| P2 | 已提交的自动化验证只覆盖站点发布构建 | 先固化已复现用例，再将两种交付纳入 PR 检查 |
| P3 | 跳过导航会切页，跨午夜的页面状态各自取时 | 保留现有 Hash 路由，统一日期来源和交互边界 |

## P1 本地数据与备份

### 1. 启动和故障恢复

**已复现。** 启动时模拟 IndexedDB 只读事务失败且本地没有备用快照，界面进入空库，随后在没有操作的情况下把空快照写回 IndexedDB。另一次模拟写事务失败，新增念头进入 `localStorage`，读回时仍优先采用旧的 IndexedDB 快照，新念头从界面消失。正常写入路径也没有清理或标记旧备用快照。 [启动读取与保存](../src/lib/storage.ts#L331) · [就绪后安排自动保存](../src/lib/store.tsx#L229)

**改进。** 让存储返回明确结果，区分已读到快照、确认空库、从备用副本恢复、数据无法读取。只在用户有实际改动或明确执行恢复后写入。无法确认原库时保留已有数据和重试入口。新写入使用带版本和修订信息的快照，明确备用副本在何时可以恢复、回写成功后何时退役。旧格式双副本无法比较时，保留两份可恢复数据，避免猜测后覆盖。清空操作也走同一条提交路径，使失效的备用数据不会在稍后恢复。

**验收。** 注入读取失败、写事务失败、主副本恢复和双层写入失败。无编辑的启动不得修改原库，备用副本中已接收的修改可以恢复，失败状态可以重试，确认清空后切换存储层不会重新出现已清数据。

### 2. 保存时序和多标签页

**已复现。** 同源两标签页先打开同一空库，A、B 分别新增念头并依次写入，最终数据库只剩 B。编辑已有念头后立即刷新，最后输入丢失。编辑器先等 700 ms 才更新应用状态，应用状态再等 300 ms 写入。关闭编辑器时先 `dispatch` 再调用 `flushSave()`，后者仍可能读到上一轮 React 渲染的快照，隐页和退出时也只会提交已经进入 store 的状态。 [编辑器提交](../src/features/ideas/IdeaSheet.tsx#L81) · [关闭编辑器](../src/features/ideas/IdeaSheet.tsx#L230) · [快照队列与页面事件](../src/lib/store.tsx#L245)

**改进。** 将尚未落盘的编辑放到保存入口能同步取得的位置。用可等待的提交接口处理“完成”、导入、清空和应用内更新。保留写入防抖，并给移动端后台或进程中断后的编辑设计本地恢复路径。以 IndexedDB 同一读写事务检查基准修订号再提交，干净页面收到更新后重读，仍有改动的页面保留自己的编辑并提示冲突。先实现检测和恢复，自动合并等出现真实需求再评估。通知只用于刷新，写入正确性由事务检查保证。备用模式也需有明确的并发行为，无法安全协调时保留待恢复编辑。

**验收。** 覆盖输入后立即刷新、点击完成后立即切页、用户主动更新 PWA、写入失败后重试。两页新增不同记录或修改同一记录时，较早提交的记录仍可读，未提交的输入可恢复。仅打开、切换或关闭未修改的页面不得写回旧快照。

### 3. 本地格式、导入和导出

**已复现。** 界面可保存 50,001 字的念头，IndexedDB 写入完整文本，刷新后缩为 50,000 字并回写。用当前导出和解析函数往返时，501 个步骤变成 500 个，401 条最近删除变成 400 条，`droppedCount` 仍为 0。原因是启动和导入共用裁剪逻辑，报告只统计念头与目标总数差额。构造 72 条各 50,000 个中文字符的念头，正常导出的文件约 10.31 MiB，超过导入界面 10 MiB 上限。外层应用标识和版本、内层数据版本也没有用于选择解析路径，未知版本能被当作 v1 读取。 [正文与步骤裁剪](../src/lib/storage.ts#L190) · [加载与导入的共同规则](../src/lib/storage.ts#L285) · [备份解析](../src/lib/storage.ts#L431) · [导入文件上限](../src/features/settings/SettingsSheet.tsx#L128)

**改进。** 将本地快照解码、显式版本迁移、外部备份校验拆成独立职责。先兼容当前 v1 导出及明确支持的旧裸格式，未知版本直接提示原因。合法的已保存记录应可无损读取和往返。对确需限制的输入在创建或编辑时统一处理，已经存在的超量记录继续可读、可导出。导入文件大小规则要与导出能力一致。可修复的外来备份在确认前显示实际影响，至少覆盖正文、步骤、收藏、最近删除和重复标识。预览同时说明哪些数据会被替换，在确认时从当前状态保留本机 Key。保留现有的备份密钥字段为空字符串的契约。

**验收。** 用当前版本导出的正常及边界夹具覆盖导出、导入、刷新后的逐字段往返。测试旧格式、未知版本、无效日期、任务与最近删除上限、超出旧文件大小上限和密钥保留。遇到不能安全导入的文件时，原库完整保留。

## P2 业务操作与交付验证

### 删除、撤回与整库操作

念头、目标、步骤均由页面先删除再加入最近删除，并各自决定提示。一个条目本身超过 5 MiB 时，现有裁剪直接从首项停止，模拟已确认会丢弃新条目及原有回收记录。任务完成后，Toast 的撤回是再次反转状态，期间若手动反转过，点击旧撤回会反向改回。导入与清空由设置页更新状态、清草稿、发全局事件并即刻显示成功，保存结果由另一层异步决定。 [念头删除](../src/features/ideas/IdeasView.tsx#L120) · [任务撤回与目标删除](../src/features/goals/GoalsView.tsx#L200) · [回收裁剪](../src/lib/trash.ts#L58) · [导入与清空](../src/features/settings/SettingsSheet.tsx#L148)

把“移到最近删除”“恢复”“替换本地数据”做成状态层的完整操作，修改和结果使用同一份当前数据。操作返回可撤回、父目标已删除、容量不足等结果，界面据此提示。单条超预算时先保留原库和回收记录，普通删除仍直接执行并可撤回。撤回精确指向原操作，过期或已失效的撤回不改动当前数据。导入和清空保存成功后再清理草稿、关闭旧编辑会话与失效提示。向 reducer 传入时间和必要标识，让状态规则可以用固定输入验证。

验收覆盖三类删除与还原、父目标先删除、预算临界值与单条超预算、手动改回后点击旧撤回、保存失败或快速重复确认。

### AI 流和会话

本地模拟 SSE 返回一段正文后直接 EOF，`polishText` 仍返回成功且 `finishReason` 为 `null`，面板进入可替换原文的状态。开始新请求、关闭和停止都能取消旧请求，但旧请求的回调及结束分支没有校验归属，还能重置当前控制器或更新共享输出。另有两个模块分别维护可选模型列表。 [流解析和结束条件](../src/lib/deepseek.ts#L313) · [面板开始与停止](../src/features/ideas/AiPolishSheet.tsx#L161) · [设置模型列表](../src/features/settings/SettingsSheet.tsx#L35) · [保存格式模型列表](../src/lib/storage.ts#L140)

将提示词、DeepSeek 客户端、面板会话状态各自归位。让每次请求拥有独立标识，只有当前会话能更新内容、结束状态和控制器。由客户端明确报告完整、已截断、主动停止或故障，面板依据结果提供操作，保护原文和撤回行为。模型标识和默认值使用单一来源。先用模拟响应验证分块中文、成功结束、半途断开、超时、停止后立即重跑、关闭再打开。验证无需真实 Key 或联网请求。

## 实施顺序

1. **先锁定回归和止损。** 固化读取失败、备用副本、长正文和多标签页的复现。禁止启动失败后的空快照写回，停止对合法已存内容的静默裁剪。用本地 v1 夹具确认原始数据仍可打开和导出。
2. **统一版本与提交边界。** 在存储层实现快照来源、修订号和恢复协议，迁移已存数据前保留可恢复副本。在状态层实现待保存编辑、冲突和整库操作，确保失败时页面保留用户输入。此阶段补齐备份往返和快速退出验收。
3. **整理领域操作和发布验证。** 将删除与撤回、AI 请求管理随对应改动提取，保留 React Context、当前页面入口和共用组件。将 PWA 和便携版验证纳入同一次检查，再处理共享日期、可访问性及展示文件拆分。

新增职责先按文件拆分。可把可测试的纯状态转移与 React Provider 分开，把浏览器存储、备份格式和草稿分开。 `features/` 继续组织业务画面和专属流程，`components/` 保持通用 UI。每步可单独验收，避免同时重写数据层、交互和打包流程。
